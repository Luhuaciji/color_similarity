# 仓库与真实数据审计

> 审计日期：2026-07-27  
> 审计范围：仓库结构、代码、依赖、配置、源 CSV、`downloaded_images/`、`image_preprocessing_output/` 与真实图片抽样  
> 代码基线：`main` 分支，提交 `462ecf2`  
> 本轮性质：阶段 0，只读数据审计与方案设计；未实现后续流水线  
> 主设计依据：`docs/codex_lip_color_pipeline_guide.md`

## 1. 结论摘要

仓库已有一套可用的基础图片预处理实现和一次覆盖全量下载图片的历史运行结果，不应重写。当前最有价值的可复用能力是：

- 原图逐字节副本和 SHA256 校验；
- EXIF 方向读取与转换；
- ICC 检查、非 sRGB 到 sRGB 转换及缺失 ICC 标记；
- Alpha Mask 独立保存；
- SHA256、pHash、dHash 和 BK-tree 近重复候选；
- 基础亮度、模糊度、分辨率指标；
- 单图失败隔离、CSV/JSONL 元数据及错误报告。

但在开始图片角色分类或模型批处理前，必须先处理以下阻断项：

| 优先级 | 阻断项 | 影响 |
|---|---|---|
| P0 | `test_qwen36_vision.py:21` 在受 Git 跟踪文件中包含明文 API Key | 密钥泄露风险；应立即轮换，并在后续代码阶段改为环境变量 |
| P0 | 下载成功结果没有来源清单，商品目录又存在多 SKU 合并 | 图片目前不能稳定追溯到 CSV 行、`asset_id`、`sku_id` 和源 URL |
| P0 | 现有预处理 `image_id` 是“路径 + 内容哈希”，主指南要求内容 SHA256 | 完全相同字节的图片被分配不同 `image_id`，会影响缓存、数据库语义和数据集划分 |
| P0 | VLM 测试脚本只打印响应，不保存请求、原始响应和解析结果 | 不满足 AGENTS.md 和主指南的审计底线 |
| P1 | 工作图路径不包含处理版本或配置指纹，日志以 `mode="w"` 覆盖 | 配置或代码变化后可能复用旧工作图，却写入新版本号；历史日志也会丢失 |
| P1 | 文件扩展名与真实解码格式不总是一致 | 143 个 GIF 和 86 个 PNG 以 `.jpg` 命名，不能按扩展名决定解码、MIME 或模型输入 |
| P1 | 数据含整页长图、极端长宽比和 1 像素装饰条 | 需要长图切片、语义无效检测和坐标回映，不能只按普通商品图处理 |
| P1 | 当前 pytest 环境不完整 | `requirements-dev.txt` 声明了 pytest，但当前 `ColorSimilarity` 环境未安装，测试套件无法直接运行 |

本轮没有修改 `downloaded_images/` 中任何文件，也没有启动完整流水线或付费模型调用。

## 2. 审计方法和统计口径

### 2.1 只读检查

执行了以下只读检查：

1. 完整阅读 `AGENTS.md` 和 1563 行主设计文档；

6. 使用下载器的现有解析函数做只读任务重放，比较“预期目标路径集合”和“实际文件路径集合”；

8. 对全部 Python 文件做 AST 语法解析；

### 2.2 统计口径

- “图片文件”指 `downloaded_images/` 中的 `.jpg` 和 `.png` 文件；失败清单 CSV 不计入图片。

- 商品图片数按物理目录 `品牌目录/商品目录/图片文件` 统计。
- 损坏情况区分：
  - 确认截断或无法完整解码；
  - 因安全/尺寸策略被拒绝，但不直接断言文件已损坏；
  - 可解码但语义无效或尺寸异常。
- 历史预处理产物标记为脚本版本 `1.1.0`，但产物没有保存 Git 提交和配置哈希，因此不能仅凭版本字符串证明它与当前文件逐字一致。

## 4. 真实数据目录组织

### 4.1 物理目录层级

当前数据严格满足以下物理层级：

```text
downloaded_images/
└── 品牌目录/
    └── 商品目录/
        └── pic_list_001_<12位URL哈希>.jpg
        └── show_pic_001_<12位URL哈希>.png
```

全量验证结果：

| 指标 | 数量 |
|---|---:|
| 品牌目录 | 101 |
| 商品目录 | 2277 |
| 图片文件 | 31,511 |
| 商品目录以下的额外嵌套目录 | 0 |
| 不在“品牌/商品/文件”深度的图片 | 0 |
| `pic_list_*` 图片 | 9743 |
| `show_pic_*` 图片 | 21,768 |
| 不符合当前命名正则的图片 | 0 |

物理层级是稳定的当前事实，但目录语义不是一对一实体关系。

### 4.2 品牌目录不是规范品牌实体

源 CSV 有 92 个非空 `brand_id`，却形成 101 个品牌目录。共有 9 个 `brand_id` 对应两个品牌目录名：

- `MAC 魅可` / `魅可`
- `Tom Ford Beauty 汤姆福特` / `汤姆福特`
- `THANN 庭润` / `庭润`
- `Bobbi Brown 芭比 波朗` / `芭比波朗`
- `POLA 宝丽` / `宝丽`
- `Estee Lauder 雅诗兰黛` / `雅诗兰黛`
- `L’occitane 欧舒丹` / `欧舒丹`
- `Laura mercier` / `罗拉玛希`
- `Laneige 兰芝` / `兰芝`

因此：

- `brand_folder` 必须原样保留；
- 品牌规范化应优先使用源 `brand_id` 和显式别名表；
- 不能用目录名直接生成最终 `brand_id`。

### 4.3 商品目录可能合并多个 SKU/色号

源 CSV 有 2309 行、2308 个唯一 `sku_id`，但只有 2277 个物理商品目录。

| 指标 | 数量 |
|---|---:|
| 多行映射到同一商品目录的碰撞组 | 16 |
| 落入这些碰撞组的 CSV 行 | 48 |
| 单个目录最多对应 CSV 行 | 5 |
| 重复的 `sku_id` | 1 个，出现于 2 行且商品拼接名不同 |

典型证据：

- `魅可-M.A.C-经典子弹头口红唇膏-3g-3g` 对应 5 个不同 `sku_id`，实际色号包含 602、108、646、650、665；
- `魅可-M.A.C-水漾晶亮唇膏-水漾子弹头-3g-3g` 对应 5 个不同色号；
- `乔治·阿玛尼-GIORGIO ARMANI-臻致丝绒哑光唇釉-6.5ml-6.5ml` 对应 405、206、529、530 四个 SKU；
- `华伦天奴-VALENTINO-哑光唇膏-3.4g-3.4g` 对应 409A、111A、219A、22A 四个 SKU。

部分旧数据的 `sku_color_no` 实际填写的是 `3g`、`5ml` 等容量，真正色号只出现在 `sku_name`。因此 `sku_color_no` 不能直接视为真值。

结论：

- 商品目录只能先作为 `folder_group`；
- 源 CSV 行必须单独建立 `source_record_id`；
- `sku_id`、`asset_id`、`goods_id` 和原始整行都要保留；
- 图片与源 CSV 行应是多对多关系；
- `product_id` 和 `shade_id` 必须在实体归一化后生成，不能仅依赖目录。

### 4.4 下载引用与物理文件

使用当前下载器解析当前 CSV 做只读重放：

| 指标 | 数量 |
|---|---:|
| CSV 图片 URL 原始引用 | 31,513 |
| 按目标路径去重后的下载任务 | 31,511 |
| 解析失败 | 0 |
| 实际图片文件 | 31,511 |
| 预期但缺失的目标路径 | 0 |
| 实际但无法由当前 CSV 重建的路径 | 0 |

说明当前 CSV 和当前下载文件集合能够完整对齐。但是下载器只写失败报告，不写成功 manifest。当前映射依赖：

- CSV 快照仍未变化；
- 文件名中的源字段、序号和 12 位 URL SHA1；
- 下载器当前的路径清洗与命名实现。

这不足以作为长期数据库血缘。后续必须显式保存 `dataset_snapshot_id → source_record_id → source_ref_id → image_occurrence_id → image_id`。

## 5. 图片格式、尺寸、损坏和商品图片数

### 5.1 扩展名与真实格式

文件扩展名：

| 扩展名 | 数量 | 占比 |
|---|---:|---:|
| `.jpg` | 27,785 | 88.18% |
| `.png` | 3726 | 11.82% |

Pillow 实际解码格式：

| 实际格式 | 数量 | 占全部图片 |
|---|---:|---:|
| JPEG | 27,555 | 87.45% |
| PNG | 3812 | 12.10% |
| GIF | 143 | 0.45% |
| 未完成格式识别 | 1 | 0.003% |

有 229 个文件（0.73%）扩展名与实际格式不一致：

- 143 个 `.jpg` 实际为 GIF；
- 86 个 `.jpg` 实际为 PNG。

抽查确认某 `.jpg` 文件头为 `GIF89a`。原因与 `download_product_images.py:151-155` 的 Windows 路径处理有关：URL path 以双斜杠开头时被 `pathlib.Path` 当作 UNC 路径，后缀识别为空并回退成 `.jpg`。

后续必须：

- 保存 `extension`、`detected_format`、`mime_type` 和 `extension_mismatch`；
- 以实际解码格式决定处理器和 Data URL MIME；
- 把 GIF 纳入显式支持范围；
- 不按文件后缀推断图片角色或真实性。

现有 143 个 GIF 均记录为单帧，但不能据此假设未来 GIF 都是单帧。

## 6. 视觉抽样结论

抽样覆盖了 JPEG、PNG、扩展名错配 GIF、透明图、普通方图、详情图、长图和极端尺寸。

| 样本 | 观察 | 对实现的要求 |
|---|---|---|
| 倩碧透明 `pic_list` | 商品瓶体和包装占主导，液体颜色可见但受容器影响 | 文件名前缀不能替代角色分类；包装/容器颜色不能直接当代表色 |
| MAC `pic_list` | 白底包装图，几乎没有可用膏体颜色 | `pic_list` 不等于可提色 |
| 完美日记 `show_pic` | 全脸模特，唇部只占局部 | 需要唇部定位、低权重和滤镜/肤色风险 |
| 橘朵 N19 `pic_list_001` | 包装、文字、唇部效果组合图 | 需要主角色和辅助角色并存 |
| 橘朵 N19 `pic_list_005` | 同图展示 N18、N19、N03、N05 | 商品文件夹中的目标色号不等于图中唯一色号；必须保留多色号空间证据 |
| 花知晓 `show_pic` | 大量文字和三个膏体示意 | OCR 有价值，但不适合直接作为商品代表色 |
| 伪装为 `.jpg` 的 GIF | 模特唇妆和宣传文字 | MIME 必须取实际格式 |
| 1074×28190 长图 | 多种角色和多组色号纵向拼接 | 需切片、tile 坐标和原图坐标回映；单一整图标签不足 |
| 750×1 PNG | 单色装饰条 | 严格解码成功不等于业务有效 |

图片角色标签体系本身仍可保留，但应补充：

- `layout_type`：`single_panel`、`collage`、`long_detail_strip`、`grid` 等；
- `is_extreme_aspect_ratio`、`is_decorative_strip`；
- tile/region 级分类和原图坐标；
- `context_shade` 与 `depicted_shades` 的区分。

### 7.2 重复图片

| 指标 | 数量 |
|---|---:|
| 唯一 SHA256 内容 | 12,386 |
| 完全重复组 | 4352 |
| 重复额外文件 | 19,125（占全部图片 60.69%） |

含义：

- 模型缓存应按内容 SHA256 复用，可显著减少调用量；
- 训练/验证/测试划分必须按 SHA256 组隔离，避免同图泄漏；
- 同一内容仍需保留多个来源 occurrence 和 SKU 关系；
- pHash 阈值尚未人工校准，且分组是连通分量，不能直接作为删除或事实合并依据。

### 7.3 ID 语义冲突

现有元数据有：

- 31,511 个唯一 `image_id`；
- 只有 12,386 个唯一 SHA256。

原因是 `preprocess_product_images.py:402-404` 将 `image_id` 定义为：

```text
SHA256前16位 + 相对路径SHA1前10位
```

它实际是 occurrence ID，不是主指南中的内容 ID。迁移时应：

- 保留现有值为 `legacy_image_id`；
- 新 `image_id` 使用完整 SHA256；
- 新增 `image_occurrence_id` 保存路径级身份；
- 不覆盖或重新解释已有字段而不留迁移记录。

### 7.4 版本和审计缺口

现有输出只保存 `processing_version=1.1.0`，没有：

- `run_id`；
- Git commit；
- 完整配置快照及 `config_hash`；
- 依赖版本快照；
- 输入数据快照 ID；
- 派生文件的变换指纹。

`preprocess_product_images.py:934` 的工作图路径只基于相对路径和源 SHA256；`overwrite=false` 时会复用已有工作图。若转换策略或配置改变，路径不变，元数据却会写入当前版本号。

`preprocess_product_images.py:353` 以覆盖模式写日志，也不满足多次运行历史留存。
