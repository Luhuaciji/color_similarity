# 色彩科学约束的多视角监督式色号相似度学习系统顶层设计

## 1. 文档目的

本文档面向口红、唇釉、唇泥、唇膏等彩妆色号数据的相似度学习系统设计。

在已完成以下工作的基础上：

- 从商品图片中提取代表色；
- 建立色号数据库；
- 从商品名称、详情页、OCR 文本和商品图片中提取色号属性；
- 提取适用肤色、冷暖皮、肤质、唇色、妆效、场景等信息；

进一步构建一个不只依赖 Hex、RGB 或传统颜色距离，还能利用结构化属性、文本、图像和人工标签进行监督学习的色号相似度系统。

本文档重点回答：

1. 该方案是否可行；
2. 应如何定义“色号相似度”；
3. 哪些属性可以作为监督学习信息；
4. 应采用什么模型和训练方法；
5. 如何组织数据、标注、训练、评估和上线；
6. 当前约 2000+ 商品规模下应如何分阶段实施。

---

## 2. 总体结论

该方案具有较高可行性，并且比仅根据 Hex 或 RGB 计算相似度更符合真实商品检索和推荐需求。

推荐将系统定义为：

> **色彩科学约束的多视角监督式色号度量学习系统。**

系统不应使用监督学习完全替代颜色科学，而应采用以下总体思路：

```text
颜色科学距离
    +
结构化色号属性
    +
商品图像特征
    +
商品文本语义
    +
人工相似度标签
    +
用户行为反馈
    ↓
多任务相似度学习与排序
```

其中：

- CIELAB、LCh、ΔE00 等指标提供稳定、可解释的色彩科学底座；
- 色系、冷暖、深浅、饱和度、妆效、质地等属性补充仅靠颜色值无法表达的信息；
- 图像和文本模型提供非结构化语义；
- 人工标签和用户反馈用于学习真实的“看起来像”“可以替代”和“适合某类用户”等关系。

最重要的设计原则是：

> **不能只训练一个万能的“色号相似度分数”，而应将不同业务目标拆分建模。**

## 3. 为什么不能只使用 Hex 或 RGB

### 3.1 RGB 不是感知均匀空间

RGB 数值主要面向显示和编码，不同方向上的数值变化并不对应相同程度的人眼感知差异。

例如：

- RGB 数值变化相同，不代表人眼感知变化相同；
- 同一 RGB 在不同显示设备上可能呈现不同；
- RGB 欧氏距离不能准确表示细微色差。

因此，颜色相似度的基础计算建议使用：

- CIELAB；
- LCh；
- CIEDE2000 色差，即 ΔE00；
- 明度差 ΔL；
- 彩度差 ΔC；
- 色相差 ΔH。

### 3.2 单一代表色无法描述真实上唇效果

单个 Hex 值不能充分表达：

- 薄涂和厚涂；
- 透明度和遮盖力；
- 哑光、柔雾、水光、镜面；
- 唇泥、唇釉、膏体的铺展差异；
- 偏光、细闪；
- 显荧光、发灰、发白；
- 不同原生唇色上的表现；
- 不同肤色背景下的视觉效果。

因此，Hex 或 ΔE00 适合描述“基础色度接近程度”，但无法独立描述“妆效相似”“商品替代”或“用户适配”。

## 4. 相似度任务定义

建议至少建立四类相互独立的任务。

| 任务 | 核心问题 | 关系类型 |
|---|---|---|
| 色度相似度 | 两个色号本身的颜色有多接近 | 对称 |
| 妆效相似度 | 两个色号上唇后的整体表现有多接近 | 对称 |
| 商品替代相似度 | 商品 B 是否可以替代商品 A | 基本对称，但可受价格、品类影响 |
| 用户适配度 | 某个色号是否适合某个用户 | 非对称 |

### 4.1 色度相似度

色度相似度只回答：

> 在标准化条件下，两个色号的颜色本身有多接近？

主要输入：

- Lab；
- LCh；
- ΔE00；
- ΔL；
- ΔC；
- ΔH；
- 冷暖方向；
- 颜色分布；
- 代表色置信度。

### 4.2 妆效相似度

妆效相似度回答：

> 两个色号上唇后，在深浅、饱和度、透明度、光泽、遮盖力和质感方面是否接近？

主要输入：

- 色度特征；
- 产品形态；
- 光泽类型；
- 遮盖力；
- 透明度；
- 哑光度；
- 柔焦度；
- 染唇性；
- 闪光或偏光；
- 上唇图像特征。

### 4.3 商品替代相似度

商品替代相似度回答：

> 当用户无法购买目标商品时，候选商品是否可以作为合理替代？

主要考虑：

- 色度；
- 妆效；
- 产品形态；
- 质地；
- 滋润程度；
- 持妆性；
- 转移性；
- 品类；
- 价格；
- 容量；
- 品牌；
- 是否停产或缺货；
- 使用场景。

该任务本质上更接近排序问题，而不是单纯的颜色分类问题。

### 4.4 用户适配度

用户适配度回答：

> 某个色号是否适合特定用户？

用户侧特征包括：

- 肤色深浅；
- 冷暖皮；
- 原生唇色；
- 唇部状态；
- 偏好色系；
- 偏好妆效；
- 使用场景；
- 价格区间；
- 品牌偏好。

该任务不应直接混入商品—商品相似度模型，而应单独建立用户—商品匹配模型。

## 5. 色号属性在监督学习中的三种用法

### 5.1 作为模型输入特征

将商品和色号属性结构化后，直接作为模型输入。

示例：

```yaml
color_family: 红棕
sub_color_family: 焦糖红棕
undertone: 暖
lightness_level: 中深
saturation_level: 中高
finish: 柔雾
coverage: 高
product_form: 唇泥
fluorescence_level: 低
suitable_skin_tones:
  - 黄一白
  - 黄二白
suitable_undertones:
  - 暖
  - 中性
occasion:
  - 通勤
  - 秋冬
```

模型可学习：

- 颜色接近时，质地差异是否影响替代关系；
- 同为红棕时，冷暖差异是否应拉开距离；
- 色度略有差异但妆效一致时，是否仍可视为替代；
- 同色系、同光泽、同遮盖力是否更容易构成替代关系。

### 5.2 作为辅助监督任务

主模型学习相似度的同时，还可以预测：

- 色系；
- 子色系；
- 冷暖调；
- 深浅等级；
- 饱和度等级；
- 光泽类型；
- 遮盖力；
- 产品形态；
- 适配肤色；
- 适配冷暖皮。

组合损失可表示为：

\[
L =
\lambda_1 L_{\text{similarity}}
+\lambda_2 L_{\text{ranking}}
+\lambda_3 L_{\text{color-family}}
+\lambda_4 L_{\text{undertone}}
+\lambda_5 L_{\text{finish}}
+\lambda_6 L_{\text{color-consistency}}
\]

这样可在相似度人工标签较少时，利用已有结构化属性约束模型，使嵌入空间保持可解释性。

### 5.3 作为弱监督标签来源

可以根据颜色和属性自动构建初始正负样本。

#### 弱正样本

满足多个条件：

- ΔE00 较低；
- 同色系；
- 同冷暖；
- 同深浅区间；
- 同妆效；
- 同产品形态。

#### 弱负样本

满足以下一个或多个条件：

- ΔE00 很高；
- 色系完全不同；
- 明度跨度大；
- 冷暖方向相反；
- 一个哑光、一个镜面；
- 一个高遮盖、一个透明；
- 产品形态差异显著。

注意：

> 商品详情中的“黄皮显白”“不挑皮”“素颜友好”等营销描述只能作为弱监督信息，不能直接作为客观真值。

## 6. 总体系统架构

### 6.1 五层架构

```text
数据采集层
    ↓
颜色与属性标准化层
    ↓
多视角特征层
    ↓
监督式相似度学习层
    ↓
检索、替代和个性化推荐层
```

### 6.2 数据流

```text
商品图片
    ├── 颜色提取
    │      └── RGB、Lab、LCh、ΔE00相关特征
    │
    ├── 图像分类
    │      └── 色卡、膏体、手臂试色、上唇、包装、对比图
    │
    └── 图像编码
           └── 颜色分布、质感、光泽、透明度、上唇效果

商品标题和色号名称
    └── 文本解析
           └── 品牌、系列、色号编号、色号名称、色系语义

商品详情和OCR
    └── 属性抽取
           └── 冷暖、深浅、饱和度、妆效、适用人群、场景

人工审核
    └── 高质量属性标签、相似度标签、排序标签

用户行为
    └── 点击、收藏、购买、替换接受、退货、评价

所有信息
    ↓
统一色号特征库
    ↓
多任务相似度模型
    ├── 色度相似度
    ├── 妆效相似度
    ├── 商品替代排序
    └── 用户适配度
```

## 9. 监督标签设计

### 9.1 不建议只做二分类

色号相似度更适合使用连续分数或有序等级。

### 9.2 色度相似度等级

| 标签 | 含义 |
|---:|---|
| 4 | 几乎无法区分 |
| 3 | 非常接近，可视为近似色 |
| 2 | 同色系，但存在明显差异 |
| 1 | 只有局部颜色属性接近 |
| 0 | 明显不同 |

### 9.3 妆效相似度等级

| 标签 | 含义 |
|---:|---|
| 4 | 上唇效果高度接近 |
| 3 | 大体接近，仅有轻微质感或深浅差异 |
| 2 | 风格接近，但不能直接替代 |
| 1 | 仅部分属性相似 |
| 0 | 完全不同 |

### 9.4 商品替代等级

| 标签 | 含义 |
|---:|---|
| 4 | 可以直接替代 |
| 3 | 大多数用户可接受 |
| 2 | 只在部分场景可替代 |
| 1 | 不建议替代 |
| 0 | 完全不能替代 |

### 9.5 优先采用三元组排序标注

相比直接询问：

> A 和 B 的相似度是多少？

更推荐询问：

> 对于目标色号 A，B 和 C 哪一个更像 A？

形成：

```text
Anchor   = A
Positive = B
Negative = C
```

训练目标：

\[
d(A,B) < d(A,C)
\]

三元组标注更容易获得稳定的一致性，也更贴近 Top-K 相似色检索任务。

## 10. 难样本设计

模型不能只学习明显不同的样本。

应重点构建以下难样本。

### 10.1 同色系但冷暖不同

```text
暖红棕 vs 冷红棕
暖豆沙 vs 冷豆沙
暖橘红 vs 蓝调正红
```

### 10.2 ΔE00 接近但妆效不同

```text
哑光豆沙 vs 镜面豆沙
高遮盖裸色 vs 透明裸色
唇泥红棕 vs 水光红棕
```

### 10.3 描述相似但实际颜色不同

```text
两者都宣称“黄皮显白”
但一个为橘红，一个为莓果红
```

### 10.4 颜色接近但产品形态不同

```text
唇泥 vs 唇釉
口红膏体 vs 透明唇蜜
高遮盖唇釉 vs 染唇液
```

### 10.5 同一系列内部邻近色号

同系列色号往往包装、图片风格和营销文本高度相似，是防止模型只记住系列模板的关键训练样本。

## 11. 模型演进路线

## 11.1 第一代：可解释规则基线

先建立不依赖监督学习的基线。

色度分数：

\[
S_{\text{color}}
=
f(\Delta E_{00},\Delta L,\Delta C,\Delta H)
\]

属性分数：

\[
S_{\text{attribute}}
=
w_1 S_{\text{family}}
+w_2 S_{\text{undertone}}
+w_3 S_{\text{finish}}
+w_4 S_{\text{coverage}}
+w_5 S_{\text{texture}}
\]

商品替代分数：

\[
S_{\text{substitute}}
=
\alpha S_{\text{color}}
+\beta S_{\text{effect}}
+\gamma S_{\text{product}}
\]

初始权重示例：

```yaml
color_score: 0.55
finish_score: 0.15
undertone_score: 0.10
coverage_score: 0.08
texture_score: 0.07
product_score: 0.05
```

该模型的作用：

- 建立可解释基线；
- 检查数据库质量；
- 生成初始最近邻；
- 发现错误属性；
- 生成后续人工标注候选；
- 作为生产系统回退方案。

## 11.2 第二代：监督式排序模型

在当前约 2000+ 商品规模下，推荐优先使用：

- LightGBM Ranker；
- CatBoost Ranking；
- XGBoost Ranking。

### 成对特征

对于色号 \(i\) 和 \(j\)，构建：

```text

abs_delta_l
abs_delta_c
circular_delta_h
same_color_family
same_sub_color_family
undertone_match
finish_match
coverage_difference
opacity_difference
texture_match
product_type_match
text_embedding_cosine
image_embedding_cosine
attribute_jaccard
confidence_min
confidence_mean
missing_field_count
```

### 排序数据格式

```text
query_id = anchor_shade_id
candidate_id
pair_features
relevance_label
```

示例：

| query_id | candidate_id | relevance |
|---|---|---:|
| N19 | N20 | 4 |
| N19 | N18 | 3 |
| N19 | N30 | 1 |
| N19 | P05 | 0 |

建议分别训练：

- 色度相似排序模型；
- 妆效相似排序模型；
- 商品替代排序模型。

不建议一开始就强行合并为一个模型。

## 11.3 第三代：多模态度量学习

当高质量标签逐渐增加后，再训练多模态深度模型。

### 模型输入分支

```text
Color Encoder
    Lab、LCh、颜色分布、置信度

Attribute Encoder
    色系、冷暖、深浅、饱和度、妆效、适配属性

Text Encoder
    商品名、色号名、详情文案、OCR文本

Image Encoder
    色卡、膏体、手臂试色、上唇图

Missing Mask
    标记字段缺失状态

Confidence Encoder
    编码数据来源和可信度
```

### 融合结构

```text
Color Encoder ──────┐
Attribute Encoder ──┤
Text Encoder ───────┼── Gated Fusion ──→ 64/128维嵌入
Image Encoder ──────┤
Missing Mask ───────┤
Confidence Encoder ─┘
```

建议输出多个嵌入空间：

```text
color_embedding
effect_embedding
substitution_embedding
```

而不是只输出一个万能向量。

### 相似度计算

\[
z_i = E(x_i)
\]

\[
S(i,j)=\cos(z_i,z_j)
\]

## 12. 损失函数设计

推荐组合损失：

\[
L =
\lambda_1L_{\text{SupCon}}
+\lambda_2L_{\text{Triplet}}
+\lambda_3L_{\text{Rank}}
+\lambda_4L_{\text{Score}}
+\lambda_5L_{\text{Attribute}}
+\lambda_6L_{\text{Color}}
\]

### 12.1 监督式对比损失

作用：

- 相似样本靠近；
- 不相似样本远离；
- 形成整体嵌入空间。

### 12.2 Triplet Loss

作用：

- 保证目标色号与近似色的距离，小于与不相似色的距离；
- 适合难负样本训练。

### 12.3 排序损失

作用：

- 直接优化 Top-K 检索顺序；
- 更贴近实际替代检索业务。

### 12.4 相似度回归损失

作用：

- 预测人工给出的 0–4 分；
- 用于分数校准；
- 便于输出可解释相似度。

### 12.5 属性辅助损失

作用：

- 预测色系、冷暖、妆效等；
- 保证嵌入保留有意义的色号语义。

### 12.6 颜色保持损失

作用：

- 避免文本或营销标签压过真实颜色关系；
- 保持色度嵌入与 ΔE00 的基本一致性。

该约束只应主要用于色度相似度头，不应强制限制商品替代头。

## 13. 标注数据构建方案

### 13.1 初始规模建议

可从以下规模开始：

```text
约200个代表性目标色号
每个目标色号20–30个候选
约4000–6000个目标—候选判断
```

### 13.2 每个目标色号的候选组成

建议包括：

- ΔE00 最近邻；
- 同色系近邻；
- 同冷暖近邻；
- 同妆效近邻；
- 同系列色号；
- 属性相近但颜色不同的难负样本；
- 颜色相近但妆效不同的难负样本；
- 随机负样本；
- 模型最不确定样本。

### 13.3 多人标注

部分样本建议由多名标注者独立判断。

记录：

- 标注者；
- 相似度等级；
- 判断依据；
- 置信度；
- 是否存在分歧。

可计算：

- 标注一致率；
- Cohen's Kappa；
- Krippendorff's Alpha；
- 等级相关性。

### 13.4 主动学习

每轮模型训练后，优先标注：

- 模型置信度最低的样本；
- 多个模型意见不一致的样本；
- 排名边界附近样本；
- 新品牌、新系列、新色系；
- 数据量较少的长尾类别。

## 14. 训练集划分与数据泄漏控制

### 14.1 错误划分方式

不能随机按图片划分训练集和测试集。

如果同一色号的不同图片进入不同集合，模型可能记住：

- 包装；
- 品牌水印；
- 系列排版；
- 背景；
- 官方色卡模板。

最终会导致测试指标虚高。

### 14.2 推荐划分方式

#### 色号级划分

同一 `shade_id` 的所有图片只能属于一个数据集。

#### 系列级划分

同一系列尽量不跨训练集和测试集。

#### 品牌隔离划分

保留部分品牌作为完全未见品牌测试集。

#### 时间外划分

后续新增商品只进入最终时间外测试集。

### 14.3 推荐至少报告三组结果

```text
随机色号划分
系列隔离划分
品牌隔离划分
```

其中品牌隔离结果更能反映冷启动泛化能力。

## 16. 在线检索架构

建议采用两阶段架构。

### 16.1 第一阶段：候选召回

候选召回可使用：

- Lab/ΔE00 近邻；
- 多模态向量近邻；
- 色系和产品类型规则过滤；
- FAISS；
- Milvus；
- pgvector；
- Elasticsearch/OpenSearch 向量检索。

召回 Top-50 或 Top-100。

### 16.2 第二阶段：监督重排

将召回候选送入排序模型：

```text
        ↓

        ↓
业务规则与硬约束过滤
        ↓
输出 Top-K
```

### 16.3 硬约束示例

根据任务可配置：

```text

必须规格不低于阈值
必须价格在允许范围
必须颜色相似度不低于阈值
不允许冷暖方向完全冲突
不允许产品形态差异过大
```

## 18. 关键风险

### 18.1 自动属性形成标签闭环

错误流程：

```text
模型从文案提取“适合黄皮”
    ↓
用“都适合黄皮”生成相似标签
    ↓
再训练模型预测“黄皮适配”
```

这只是复制原始文案，并未产生独立知识。

解决方法：

- 引入人工判断；
- 引入用户反馈；
- 引入不同肤色模特试色；
- 引入上唇图像；
- 引入多来源交叉验证。

### 18.2 将适用肤质误当作颜色特征

“适合干皮”更多反映滋润度和拔干程度，不代表色号接近。

建议：

```text
适用肤色 → 色号推荐模型
冷暖皮 → 色号推荐模型
原生唇色 → 上唇效果模型
适用肤质 → 产品体验和用户适配模型
```

### 18.3 文本特征压过真实颜色

两个商品可能都被描述为“显白红棕”，但实际色差明显。

解决方法：

- 独立保留 Lab/ΔE00 分支；
- 设置颜色保持损失；
- 对营销文案降权；
- 区分官方明确属性和模型推断属性；
- 为不同任务设置不同特征权重。

### 18.4 只保存一个代表色

单个 Hex 无法表示：

- 薄涂和厚涂；
- 透明度；
- 颜色分布；
- 光泽；
- 遮盖能力；
- 上唇表现。

建议至少保存：

```text
中心颜色
主色
次色
颜色离散程度
透明度
明度
彩度
色相
光泽
遮盖力
```

### 18.5 自动构造的色号对并非独立样本

2000 个色号理论上可以形成约 200 万对，但这些样本高度共享相同商品和属性，实际独立信息量远低于 200 万。

应采用：

- 商品级划分；
- 系列级划分；
- 难样本采样；
- 样本权重；
- 主动学习；
- 品牌冷启动测试。

## 22. 验收标准建议

### 数据层

- 95% 以上色号具有唯一 ID；
- 所有颜色值均可追溯到原始图片；
- 所有自动属性均保存来源和置信度；
- 缺失值与真实零值严格区分；
- 同一色号图片不跨训练集和测试集。

### 基线层

- 可输出 ΔE00 最近邻；
- 可解释每个候选的主要相似和差异原因；
- 规则权重可配置；
- 可分别输出色度、妆效和替代分数。

### 监督模型层

- NDCG@10 明显高于 ΔE00 基线；
- 品牌隔离测试中仍保持可接受性能；
- 难样本排序准确率高于规则基线；
- 颜色相似度头不被营销文本明显干扰；
- 模型结果可以回溯到输入特征和证据。

### 生产层

- 支持新色号增量入库；
- 支持 Top-K 候选召回和重排；
- 支持规则硬过滤；
- 支持模型版本和特征版本管理；
- 支持人工纠错和反馈回流。

## 23. 最终推荐

本项目应采用以下技术路线：

```text
颜色科学标准化
    ↓
建立多视角色号数据库
    ↓
构建色度、妆效、替代、用户适配四类任务
    ↓
利用色号属性作为输入特征、辅助任务和弱监督信号
    ↓
建立 ΔE00 与规则基线
    ↓
构建人工成对和三元组标注
    ↓
训练 LightGBM/CatBoost 排序模型
    ↓
进一步训练多模态监督式度量学习模型
    ↓
采用“向量召回 + 监督重排 + 规则约束”
    ↓
引入用户反馈形成个性化推荐闭环
```

最终不应只输出一个“综合色号相似度”，而应至少提供：

- 色度相似度；
- 妆效相似度；
- 商品替代分数；
- 用户适配分数；
- 主要相似原因；
- 主要差异原因；
- 结果置信度。

项目成败的关键不在于模型是否足够复杂，而在于：

1. 不同类型的相似度是否被严格拆分；
2. 自动提取属性是否保存证据和可信度；
3. 人工标签是否真正对应业务目标；
4. 测试集是否避免系列和品牌泄漏；
5. 模型是否保留颜色科学约束和可解释性。
