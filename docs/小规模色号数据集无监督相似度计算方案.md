## 2. 修改原因与当前实证

### 2.1 为什么必须修改

Stage 2.6 的真实数据库输出是 `quick_color_regions`，一张图片可以有零个、一个或多个颜色区域。区域可能是 `swatch`、`lip`、`bullet`、`product_fill` 或 `other`，也可能缺少色号文字、与多个代码冲突、无法映射业务 SKU，或只有低质量颜色。

因此，下列旧假设不成立：

- 一张图片等于一个业务色号；
- 一个色号天然有唯一 Hex；
- 所有提取颜色都适合进入正式索引；
- OCR 色号必然能唯一映射到 `sku_id_raw`；
- 相同文本代码可以不看图片来源直接跨图合并。

### 2.2 数据库证据

本设计依据当前 workspace 的以下真实表：

- `quick_image_extractions`：Stage 2.6 整图结果和状态；
- `quick_text_items`：文字、文字类型和原图 bbox；
- `quick_color_regions`：区域类型、关联文字、颜色及质量；
- `image_occurrences`、`source_ref_occurrences`、`source_image_refs`、`source_records`：图片到业务记录的可追溯关系；
- `dataset_snapshots`：稳定实体 ID 的数据集命名空间。

版本化清单 `configs/samples/observed_similarity_mvp_sources_v1.jsonl` 固定选择 39 张 canonical 图片：

## 3. 第一版任务边界

### 3.1 数据流

```text
版本化 source manifest
  → 选择唯一的 Stage 2.6 图片结果
  → 将每个颜色区域落为审计 observation
  → 解析唯一色号代码
  → 解析业务 SKU 或生成图片内临时身份
  → 仅保留 medium/high swatch 进入正式 profile
  → 用未加权 ΔE00 medoid 选代表观测
  → 计算同 profile 类型的 CIEDE2000 上三角 pair
  → 生成双向 Top-K
  → SQLite + CSV + JSON
```

### 3.2 明确不做

第一版不加入：

- Qwen、OCR 或任何在线 API 调用；
- RGB 欧氏距离、HSV/HSL 加权距离或学习权重；
- 文本、商品属性、价格、品牌加分；
- 图像 embedding、聚类、PCA 或监督训练；
- `lip`、`bullet`、`product_fill`、`other` 的跨类型混排；
- `low` 颜色进入正式索引；
- 人工审核门禁；
- 将展示分数解释为概率；
- 将图片内临时色号伪装成业务 SKU。

其他区域和低质量颜色仍写入 observation，作为诊断证据。

## 4. Source manifest

### 4.1 格式

每行是一个 JSON 对象，schema 为 `observed-similarity-source-1.0`，至少包含：

```json
{
  "schema_version": "observed-similarity-source-1.0",
  "manifest_version": "1.0.0",
  "sequence": 1,
  "image_id": "<sha256>",
  "sha256": "<same sha256>",
  "source_quick_run_id": "<stage2.6 run id>",
  "selection_reason": "<reason>"
}
```

### 4.2 硬校验

- `sequence` 必须从 1 连续、唯一；
- `image_id` 必须是 64 位小写 SHA256；
- `sha256` 必须等于 `image_id`；
- 同一清单不得重复图片；
- 来源 run 必须是 `stage2.6`；
- 来源 `quick_image_extractions` 必须是 `success`；
- 来源语义必须是 `image_observed_color_candidate`；
- `image_id + source_quick_run_id` 必须精确存在。

`plan` 不隐式选择“最新 run”，也不把相同图片的多个历史结果混在一起。

## 5. 区域观测与正式资格

### 5.1 所有区域都落库

每个 canonical 图片的每个 `quick_color_regions` 行都生成一条 `shade_color_observations`。即使区域不合格，也必须保存：

- Stage 2.6 run、图片、区域和关联文字 ID；
- 原始色号文字与标准化代码；
- bbox、区域类型和模型关联置信度；
- Hex、RGB、Lab、有效像素、簇占比和离散度；
- 业务或临时身份解析证据；
- 全部排除原因；
- 算法版本。

### 5.2 正式资格

一个区域只有同时满足以下条件，`formal_eligible` 才能为 1：

1. source manifest 指向成功的整图结果；
2. `extraction_status = succeeded`；
3. 来源语义为 `image_observed_color_candidate`；
4. `region_type = swatch`；
5. `color_confidence ∈ {medium, high}`；
6. Hex、RGB、Lab 完整且互相一致；
7. 从 RGB 重算 Lab 后，最大分量误差不超过 `1e-6`；
8. 有关联的 `shade_code` 文字；
9. 所有关联色号文字只产生一个唯一代码；
10. `association_confidence` 非空；
11. 已得到业务或图片内临时 `shade_id`。

任何条件失败都不阻止 observation 落库，只阻止它进入正式 profile。

## 6. 色号代码标准化

### 6.1 规则

先对文字做 Unicode NFKC，再转大写，然后提取“至少含一个数字”的代码 token。前导 `#` 和其后的空格不属于代码。

示例：

| 原文 | 标准化结果 |
| --- | --- |
| `# V01` | `V01` |
| `#602 CHILI` | `602` |
| `模特所用色号为 #400` | `400` |
| `A12 / B20` | 冲突，排除 |
| `WHITE PEACH` | 无含数字代码，排除 |

若多个关联文字都解析为同一个代码，可以进入后续步骤；若得到多个不同代码，则记为 `shade_code_ambiguous`。

### 6.2 别名与合并范围

- 同一图片内，相同标准化代码使用同一个临时 `shade_id`；
- `#602 CHILI`、`# 602` 和 `602` 因此可以在同图合并；
- 已唯一解析到同一业务 SKU 的跨图观测可以按业务 `shade_id` 聚合；
- 未解析候选绝不只凭代码相同跨图片合并。

最后一条是防止不同品牌或商品恰好使用相同代码时发生错误合并。

## 7. 业务身份与图片内临时身份

### 7.1 精确业务匹配

从当前图片 occurrence 可追溯到的 `source_records` 中读取 `sku_color_no_raw`，用与 OCR 相同的标准化规则处理，然后与区域代码精确匹配。

身份规则：

| 条件 | `identity_status` | 行为 |
| --- | --- | --- |
| 恰有一个非空 `sku_id_raw` | `business_resolved` | 使用业务稳定 ID |
| 没有匹配 SKU | `image_local_unmatched` | 使用图片内临时 ID |
| 匹配到多个不同 SKU | `image_local_ambiguous` | 使用图片内临时 ID并保存候选 SKU |
| 无唯一代码或区域不具备身份 | `excluded` | 不进入正式 profile |

稳定 ID 的逻辑命名空间：

```text
business shade_id =
  stable_id("shade_sku", dataset_snapshot_id, sku_id_raw)

image-local shade_id =
  stable_id(
    "shade_local",
    dataset_snapshot_id,
    image_id,
    normalized_shade_code
  )
```

### 7.2 正式 Top-K 如何处理无法唯一映射 SKU 的候选

第一版正式索引同时纳入：

- `business_resolved`；
- `image_local_unmatched`；
- `image_local_ambiguous`。

图片内临时候选既可以作为 query，也可以作为 candidate，但必须遵守以下硬约束：

- 始终输出 `identity_status`、`image_id`、标准化代码和来源区域证据；
- 不填造 `source_sku_id_raw`；
- 不允许通过相同代码跨图合并；
- 不允许下游把临时 ID 当成可下单或可替代的业务 SKU；
- `image_local_ambiguous` 必须保留全部候选 SKU ID；
- 后续实体规则改进时创建新版本 run，不回写篡改历史结果。

这样既不会丢掉当前图像中可用的颜色候选，也不会制造错误的业务唯一性。

## 8. Swatch profile

### 8.1 分组

第一版只创建：

```text
group key = shade_id + representation_profile
representation_profile = swatch
```

不同 region type 不得放入同一 profile，也不得在同一 Top-K 中比较。

### 8.2 代表观测：未加权 ΔE00 medoid

对同一 profile 的合格 Lab 观测集合 \(X=\{x_1,\dots,x_n\}\)，代表观测为：

\[
x^*=\arg\min_{x_i \in X}\sum_{j=1}^{n}\Delta E_{00}(x_i,x_j)
\]

不平均 Hex、RGB 或 Lab。代表 Hex/RGB/Lab 必须来自一条真实 observation。

总距离并列时依次选择：

1. `color_confidence` 更高；
2. `cluster_proportion` 更高；
3. `dispersion` 更低；
4. `shade_color_observation_id` 字典序更小。

profile 同时保存：

- 合格 observation 数；
- 证据图片数；
- medoid observation ID；
- profile 内 pair 数；
- profile 内 ΔE00 中位数和最大值；
- 全部 observation、图片和 source record 证据。

只有一个观测时标记 `single_observation_provisional`；多个观测时标记 `multi_observation_provisional`。两者都仍是图片观测基线，不是真值认证。

## 9. 颜色标准化与完整性校验

### 9.1 Hex 和 RGB

- Hex 内部统一为大写 `#RRGGBB`；
- 不接受三位缩写或八位 Alpha Hex；
- RGB 每个通道必须是 0–255 的整数；
- Hex 与 RGB 必须逐通道一致。

### 9.2 sRGB D65 到 CIELAB

复用 Stage 2.6 的确定性转换：

```text
8-bit sRGB
  → [0,1] sRGB
  → inverse companding
  → XYZ D65
  → CIELAB D65
```

数据库 Lab 不直接盲信。每条有颜色的 observation 都从 RGB 重算 Lab，并验证：

\[
\max(|Lab_{stored}-Lab_{recomputed}|)\le 10^{-6}
\]

不满足时保存错误证据并排除正式计算。

## 10. 距离、诊断和展示分数

### 10.1 唯一排序距离

唯一排序距离是 CIEDE2000：

\[
\Delta E_{00}
\]

实现采用 \(k_L=k_C=k_H=1\)。不得再对明度、彩度或色相分量二次加权，否则算法不再是标准 CIEDE2000。

实现必须满足：

- 恒等性；
- 对称性；
- 非负性；
- 零彩度稳定；
- 0°/360° 色相环绕正确；
- 完整标准参考向量误差不超过 `1e-4`。

### 10.2 诊断字段

每个 pair 额外输出：

\[
\Delta L=|L_1-L_2|
\]

\[
\Delta C=|C_1-C_2|
\]

\[
\Delta h=\min(|h_1-h_2|,360-|h_1-h_2|)
\]

这些字段只解释差异，不参与排序或分数计算。

### 10.3 展示分数

\[
score=\frac{100}{1+(\Delta E_{00}/10)^2}
\]

映射版本为 `inverse-quadratic-d10-v1`。分数只用于展示，不能解释为概率、准确率或业务替代度。

### 10.4 未校准操作型距离带

| 概念等级 | 数据库值 | ΔE00 |
| --- | --- | ---: |
| A | `de00_le_2` | `≤ 2` |
| B | `de00_gt_2_le_5` | `(2, 5]` |
| C | `de00_gt_5_le_10` | `(5, 10]` |
| D | `de00_gt_10_le_20` | `(10, 20]` |
| E | `de00_gt_20` | `> 20` |

这些只是便于操作的区间，没有 ground truth 校准，不得命名为“肉眼不可分辨”“高替代”等质量结论。

`pair_quality_tier` 取两端 `color_confidence` 的较低者，仅作诊断，不修改距离或分数。

## 11. Pair 和 Top-K

### 11.1 Pair

对每个 representation profile 独立计算上三角：

\[
N_{pairs}=\frac{n(n-1)}{2}
\]

固定保存较小的 profile ID 为 A，较大的为 B，不保存反向重复 pair，不允许自身 pair。

实现按 NumPy block 计算并分批写 SQLite，不能把接近 200 万个 Python 字典一次放入内存。默认：

```text
pair_block_size = 256
pair_insert_batch_size = 5000
```

### 11.2 Top-K

将上三角 pair 通过 SQL `UNION ALL` 展开为双向候选，再用窗口函数分 query 排名。

默认：

```text
top_k = 10
max_delta_e00 = null
```

排序键固定为：

1. `delta_e00` 升序；
2. `delta_l` 升序；
3. `delta_c` 升序；
4. `candidate_shade_id` 升序。

Top-K 不允许自身候选，且同一 query 下 rank 和 candidate 都必须唯一。

## 12. 数据库 Schema 008

### 12.1 `shade_similarity_inputs`

保存每张 canonical 图片、指定 Stage 2.6 run、manifest、顺序和选择理由。一张图片在一个 similarity run 中只能出现一次。

### 12.2 `shade_color_observations`

保存全部区域及其正式资格、排除原因、文字关联、业务/临时身份、颜色和算法证据。每个 similarity run 中，一个 `quick_color_region_id` 只能落一次。

### 12.3 `shade_color_profiles`

保存 `shade_id + representation_profile` 的 medoid、质量、支持数和内部离散度。

### 12.4 `shade_similarity_pairs`

保存固定上三角 pair、CIEDE2000、展示分数、距离带和诊断字段。数据库约束 pair 两端 profile 不同且顺序固定。

### 12.5 `shade_similarity_topk`

保存双向 Top-K 视图结果。数据库约束：

- query 与 candidate 不同；
- 同 query + candidate 唯一；
- 同 query + rank 唯一；
- pair、query profile 和 candidate profile 都有外键。

完整追溯路径：

```text
Top-K
  → pair
  → profile
  → representative/all observations
  → quick_color_regions + quick_text_items
  → quick_image_extractions
  → image_id / image_occurrences
  → source_records
```

## 15. 失败、恢复和逻辑回滚

- `plan` 发现 manifest、来源状态或 Lab 完整性问题时直接失败，不写入 similarity run；
- `run` 失败时记录 pipeline run 的错误类型和脱敏消息；
- `--resume` 只允许相同 stage/config/code/manifest fingerprint；
- 原始图片、Stage 1 数据库和历史 Stage 2.6 run 始终只读；
- 逻辑回滚只需停止下游读取指定 similarity run；
- 如需物理清理，只能删除明确指定 run 的五张下游表记录和该 run 导出目录，不能递归清理 workspace 或原图目录；
- 不通过回写旧 observation 的方式“修正”身份；规则变化应创建新版本 run。

## 16. 已知限制与后续工作

当前结果只证明工程闭环可运行。主要限制：

- OCR 或关联错误会产生错误代码；
- 图片光照、压缩、屏幕显示和后期处理会影响观测色；
- 单观测 profile 的稳定性未知；
- 临时候选没有业务唯一性；
- ΔE00 阈值没有用本项目标注数据校准；
- swatch 相似不等于产品或妆效相似。

后续只有在获得人工或业务 ground truth 后，才评估：

- 色号代码和 SKU 解析准确率；
- swatch bbox/颜色准确度；
- Top-K 相关性；
- 操作距离带校准；
- 是否引入身份消歧、更多 representation profile 或多模态 rerank。
